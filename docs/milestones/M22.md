# M22 · Offline support (PWA shell → offline-first)

> Size: L · Depends on: M10, M12

## Goal

Make TransformMyNotes usable on flaky or absent connectivity, delivered
**incrementally** so value lands early and the heavy architectural decision is
deferred behind an explicit gate. Today the app is **server-rendered Next.js
(SSR) on Lambda** loaded over the network — both in the browser and inside the
Capacitor Android shell (a thin WebView onto `app.transformmynotes.com` via
`server.url`, with **no offline capability**). This milestone adds, in order:

1. a **PWA service-worker app shell** + branded offline page (no SSR change;
   benefits web + Android shell);
2. an **offline read cache** for previously-viewed notes/library;
3. **offline mutations + sync**;
4. a **decision gate** on the **static export / SPA decouple + Capacitor static
   bundle** (the only path to launching with zero network — a fork that may
   become its own milestone).

Guiding principle: **earn offline capability without losing the "every web
deploy is instantly live in the app" benefit** of `server.url`. Caching must be
versioned + update-prompted.

## In scope

- Workbox service worker (precache app shell + static assets; runtime caching)
  registered in `packages/application`.
- `manifest.webmanifest` + branded offline fallback page; Capacitor
  `www/offline.html` wiring.
- SW update UX ("new version available — reload") so users never get trapped on
  stale UI.
- Offline read cache: SWR caching of note/library GETs + IndexedDB read store +
  "offline/cached" indicator.
- Offline mutations + sync: IndexedDB queue, Background Sync replay,
  version-guarded LWW conflict handling, offline capture queue.
- Auth-aware caching (namespace per `sub`, purge on sign-out).
- Spike + go/no-go decision doc for the static-export fork; (if go) client-token
  auth + static bundle + Capacitor `webDir` switch.

## Out of scope

- Offline AI generation (Bedrock OCR / study gen / Polly TTS are server-only —
  offline only queues).
- Real-time collaboration / CRDT merge (cap at version-guarded LWW with surfaced
  conflicts).
- iOS.

## Architecture & decisions

- **SW first, not static export:** `output: 'export'` can't work against the
  current app without a rewrite — `proxy.ts` verifies the Cognito JWT
  server-side, and the app needs API routes + DynamoDB + SSR. A service worker
  layers on top of SSR with **no** architecture change and benefits the
  Capacitor WebView automatically.
- **Staleness trade-off (critical):** `server.url` makes every deploy instantly
  live; a precache risks stale UI. Use network-first for the document, a
  versioned precache, and an enforced update prompt.
- **Static-export fork (Phase 4):** launching with zero network requires a
  client SPA + client-token auth + bundled `webDir` — a product-wide change,
  gated behind a spike and likely promoted to its own milestone (provisionally
  **M23**) on a "go".

## Phases & tasks

Phases are dependency waves — **sequential**; tasks within a phase run in
parallel.

### M22.1 · Phase 1 — PWA app shell + offline fallback (no SSR change) → #493

Adds a service-worker app shell + branded offline experience **without changing
the SSR architecture** — benefits the website and the Capacitor Android shell
automatically. Tasks are independent and built in parallel by subagents.

- **M22.1.1 (M)** — Service worker + Workbox precache of the app shell + Next
  static assets + registration; runtime strategies (network-first document to
  keep deploys fresh, cache-first hashed assets).
- **M22.1.2 (S)** — `manifest.webmanifest` (brand icons, `display: standalone`,
  theme `#FAF8F3`) + branded offline fallback page + wire the Capacitor
  `www/offline.html` network-error fallback.
- **M22.1.3 (S)** — SW update UX ("new version available — reload") wired to the
  `waiting`/`controllerchange` lifecycle so users never get trapped on stale UI;
  document the versioning strategy.

**Key constraint:** caching must **not** defeat the `server.url` "deploys are
instantly live" benefit — versioned precache + enforced update prompt (see
Risks).

### M22.2 · Phase 2 — Offline read cache (view notes & library offline) → #494

Cache GET data so previously-viewed notes and the library render offline.
Depends on Phase 1 (#493). Tasks are independent and built in parallel.

- **M22.2.1 (M)** — Stale-while-revalidate runtime caching in the SW for the
  read API surface (library list, note metadata/body); cache-key + eviction
  policy.
- **M22.2.2 (M)** — IndexedDB read store + a read-through data layer so
  `NoteView`/Library hydrate from cache offline; "offline / showing cached" UI
  indicator.
- **M22.2.3 (S)** — Auth-aware caching: namespace caches per user (`sub`), never
  serve cross-user data, purge SW caches + IndexedDB on sign-out.

### M22.3 · Phase 3 — Offline mutations & sync → #495

Create/edit notes offline, queue them, sync on reconnect, with conflict
handling. Depends on Phase 2 (#494). Tasks are independent and built in parallel.

- **M22.3.1 (L)** — IndexedDB mutation queue + Background Sync replay (with a
  foreground reconnect fallback); idempotent replay + ordering.
- **M22.3.2 (M)** — Conflict-resolution model: version/`updatedAt`-guarded
  last-write-wins on API + client, with surfaced conflicts (no silent clobber of
  a newer server copy).
- **M22.3.3 (M)** — Offline capture queue: store captured photos locally, defer
  upload→Bedrock transcribe until online; "will process when you're back online"
  UX.

### M22.4 · Phase 4 — Decision gate: static export / SPA decouple (architecture fork) → #496

The **only** path to launching with *zero* network — but a product-wide
architecture fork, so it's **decision-gated**. Depends on Phase 3 (#495).

- **M22.4.1 (M) — spike + go/no-go decision doc.** Assess `output: 'export'` vs
  a client-rendered SPA: what breaks (`proxy.ts` middleware, SSR pages,
  API-route coupling), the required auth-model change, the Capacitor `webDir`
  switch, effort estimate, recommendation. **Gates the rest of the phase — run
  first.**
- **M22.4.2 (L) — (if go) client-token auth model** replacing the server
  middleware gate.
- **M22.4.3 (L) — (if go) static bundle + Capacitor `webDir` switch + CI.**

## DoD (per phase)

- **P1:** SW registers; cached shell launches instantly; offline → branded
  offline page (browser + Android), not the raw error; post-deploy update prompt
  works (no stale-UI trap).
- **P2:** a note/library opened online re-opens offline from cache;
  "offline/cached" indicator; sign-out purges (no cross-user leakage).
- **P3:** offline edit syncs on reconnect; conflicting newer server copy
  surfaced not clobbered; offline capture queues + transcribes once online.
- **P4:** committed decision doc with go/no-go; if go, follow-on scheduled
  (likely M23).

## Risks / open questions

- Stale-UI vs instant-deploy (biggest risk) — versioned precache + network-first
  document + update prompt.
- Auth + caching security (cross-user leakage; future client-token storage).
- Conflict-resolution scope creep (cap at version-guarded LWW).
- SW + Capacitor WebView quirks (verify on a real device).
- Phase 4 is product-wide, not mobile-only — gated, may become M23.

## Status / Next steps / Gotchas

- **Status:** scoped & on the board (Ready). Not started. Phases are sequential;
  start with **M22.1 (#493)**.
- **Gotcha:** the #1 design constraint is not breaking the `server.url`
  instant-deploy benefit with aggressive caching.
