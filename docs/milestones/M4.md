# M4 · Capture → Transcribe (Bedrock OCR)

> Size: L · Depends on: M1 (auth + infra baseline), M2 (library shell + DynamoDB core)

## Goal

Deliver the end-to-end path from the user's phone camera (or photo library) to a raw Markdown
transcription in S3, gated by a processing state screen and surfacing a clean error/retry state
when the image is unreadable.

The Capture screen must feel native on a phone — full-viewport camera viewfinder using
`getUserMedia`, edge-detect corner brackets (gold, matching the design), a shutter button,
and a separate "Upload" path via `<input type="file" accept="image/*" capture="environment">`.
All image data is resized client-side before leaving the device. A presigned S3 PUT keeps
raw bytes off the Next.js server. The OCR call uses the Bedrock Converse API with an explicit
`maxTokens`, a cross-region inference profile for a Claude Sonnet vision model, and a
Brazilian-Portuguese-aware prompt that preserves accents and emits clean Markdown. The
Processing state (design `StateProcessing`) shows progress steps; the error state (design
`StateError`) gives actionable retake guidance.

## In scope

- `Capture` screen: `getUserMedia` viewfinder, gold corner-bracket edge-detect affordance,
  shutter capture, "Upload" file-input path, "Flip" camera toggle (front/back).
- Client-side image resize + JPEG re-compress (target ≤ 1 MB) before upload, using
  `<canvas>` — no third-party library required.
- Route handler `POST /api/notes/upload-url` — issues a presigned S3 `PutObject` URL
  scoped to the authenticated user's prefix. Returns `{ presignedUrl, s3Key }`.
- Client uploads directly to S3 via the presigned URL (PUT, no proxy through Next.js).
- Route handler `POST /api/transcribe` — accepts `{ s3Key }`, reads the image from S3,
  calls Bedrock Converse with a Sonnet vision inference profile, returns
  `{ markdown, wordCount, detectedLang, ocrConfidence }`.
- `StateProcessing` screen: animated progress steps (page detected → text recognised →
  finding highlights), indeterminate/progress bar, OCR % badge.
- `StateError` screen: blurry-page visual, tips (light / flat / full frame), "Retake"
  + "Upload a clearer photo" CTAs.
- Bedrock retry logic: up to 3 attempts with exponential back-off on `ThrottlingException`
  and transient 5xx; propagate a structured error on permanent failure.
- DynamoDB `TranscriptionJob` item: tracks `status` (pending / processing / done / error)
  so a page refresh can poll / resume rather than losing the in-flight job.
- `BEDROCK_INFERENCE_PROFILE_ID` SST secret (SCREAMING_SNAKE_CASE); fails loudly if unset.
- S3 bucket for note assets (images + Markdown bodies); wired in `infra/storage.ts`; linked
  to `application` + `jobs` in their respective infra modules.
- Least-privilege IAM: `bedrock:InvokeModel` scoped to the single inference profile ARN;
  S3 permissions scoped to the one bucket + user-prefix path.
- Resource tagging: `Project=TransformMyNotes`, `Stage=$app.stage` on bucket and IAM policy.
- Unit tests: prompt builder, Markdown post-processing (strip Bedrock preamble, normalise
  accented chars, trim artefacts). Bedrock itself is mocked.
- Browser UI test: capture → processing → markdown returned (mock Bedrock in test env).

## Out of scope

- Saving the transcription to the permanent Notes table (M5).
- The block editor or any note-editing UI (M5).
- Review-before-save screen (M5).
- Highlight / tag features (M5).
- Offline queue / service-worker caching (post-M5).
- Multi-page / batch capture.
- Video mode.

## Architecture & decisions

### S3 bucket (`infra/storage.ts`)

New SST resource file `infra/storage.ts` — do NOT place bucket config inline in
`application.ts`. Import from `sst.config.ts` after `auth` and before `application`.

```
const notesBucket = new sst.aws.Bucket("NotesBucket", {
  tags: { Project: "TransformMyNotes", Stage: $app.stage },
});
```

CORS on the bucket allows `PUT` from the app domain so the presigned URL direct-upload works
from the browser without a proxy. Block all public access; no static website hosting.

Link `notesBucket` to `application` and `jobs` so `Resource.NotesBucket.name` is available
server-side.

### IAM — least privilege

In `infra/application.ts`, grant the Lambda/server role only:

- `s3:PutObject` + `s3:GetObject` scoped to `arn:aws:s3:::${notesBucket.name}/users/*`
- `s3:GetSignedUrl` (client-side presign is handled by `@aws-sdk/s3-request-presigner` —
  the server signs using its own credentials; no separate IAM action needed beyond `s3:PutObject`)
- `bedrock:InvokeModel` scoped to
  `arn:aws:bedrock:us-east-1::foundation-model/${Resource.BEDROCK_INFERENCE_PROFILE_ID.value}`

No wildcards. Tag the inline policy: `Project=TransformMyNotes`.

### S3 key schema

User-scoped prefixes keep IAM conditions simple and prevent cross-user reads:

```
images/users/<cognitoSub>/<ulid>.jpg       # original photo (set via presigned PUT)
markdown/users/<cognitoSub>/<ulid>.md      # transcription output (written server-side)
```

Key builders live in `packages/core/src/db/keys.ts` (storage section):

```ts
export const storageKeys = {
  originalImage: (sub: string, id: string) => `images/users/${sub}/${id}.jpg`,
  noteMarkdown:  (sub: string, id: string) => `markdown/users/${sub}/${id}.md`,
};
```

### DynamoDB — TranscriptionJob

Added to `infra/db.ts`. Single-table pattern; uses the main `Notes` table defined in M5 — but
the `TranscriptionJob` item lives under a separate PK prefix so it can be written in M4 without
depending on the full Notes schema.

```
PK:  USER#<cognitoSub>
SK:  JOB#<ulid>
attrs:
  status:    "pending" | "processing" | "done" | "error"
  s3Key:     string          # images/users/<sub>/<ulid>.jpg
  createdAt: ISO-8601
  updatedAt: ISO-8601
  errorMsg?: string
  jobId:     string          # same as the ULID in SK
```

**No GSI needed for M4** — jobs are always fetched by PK+SK (user + jobId). The job item is
ephemeral; M5 will replace it with the permanent Note item on save.

Key builder in `keys.ts`:

```ts
export const jobKeys = {
  pk:  (sub: string)           => `USER#${sub}`,
  sk:  (jobId: string)         => `JOB#${jobId}`,
  gsi: undefined,              // no GSI in M4
};
```

### Route handlers

#### `POST /api/notes/upload-url`

Auth: `proxy.ts` middleware (JWT verified).

Request body: `{ contentType: "image/jpeg" | "image/png" | "image/heic" }`

Logic:
1. Extract Cognito `sub` from verified JWT claims.
2. Generate a ULID (`jobId`).
3. Write a `TranscriptionJob` item with `status: "pending"` to DynamoDB (via `ddb` client).
4. Generate a presigned `PutObject` URL using `@aws-sdk/s3-request-presigner`; TTL = 5 min.
5. Return `{ presignedUrl, s3Key, jobId }`.

Response shape:
```json
{ "presignedUrl": "https://...", "s3Key": "images/users/<sub>/<ulid>.jpg", "jobId": "<ulid>" }
```

Fail loudly if `Resource.NotesBucket.name` is unset (will throw at import time via SST binding).

#### `POST /api/transcribe`

Auth: `proxy.ts` middleware.

Request body: `{ jobId: string }`

Logic:
1. Validate `jobId`; look up `TranscriptionJob` — reject if not found or sub mismatch.
2. Update job `status → "processing"`.
3. Fetch the image bytes from S3 (`GetObjectCommand`).
4. Call Bedrock Converse (see below).
5. On success: write Markdown to S3 (`markdown/users/<sub>/<ulid>.md`); update job
   `status → "done"`.
6. On permanent error: update job `status → "error"`, set `errorMsg`.
7. Return `{ markdown, wordCount, detectedLang, ocrConfidence, markdownS3Key }`.

Retry: wrap the Bedrock call in a helper `withBedrockRetry(fn, { maxAttempts: 3 })` that
catches `ThrottlingException` and 5xx variants, sleeps `200 * 2^attempt` ms, and re-throws
after exhausting attempts.

Fail loudly on startup:
```ts
const profileId = Resource.BEDROCK_INFERENCE_PROFILE_ID.value;
if (!profileId) throw new Error("BEDROCK_INFERENCE_PROFILE_ID is not set");
```

### Bedrock Converse — specifics

- **API**: `BedrockRuntimeClient` → `ConverseCommand` (NOT `InvokeModelCommand`).
- **Model ID**: value of `Resource.BEDROCK_INFERENCE_PROFILE_ID.value`; the deployed value
  must be the cross-region inference profile id, e.g.
  `us.anthropic.claude-sonnet-4-5-20251120-v1:0` (verify via
  `aws bedrock list-inference-profiles --region us-east-1` before seeding the secret).
- **`maxTokens`**: set explicitly — `4096` for most study pages. Must never be omitted.
- **Image content block**: pass the image bytes as a base64-encoded `image` content block
  inside the `messages` array (Converse API `ImageBlock`).
- **Prompt strategy** (system prompt + user turn):

  System prompt (English, concise):
  > You are an expert transcription assistant specialising in handwritten study notes,
  > including notes written in Brazilian Portuguese or that contain Portuguese/Spanish
  > vocabulary. Your task is to convert the handwritten page in the image into clean,
  > well-structured Markdown. Rules: (1) Preserve all accented characters exactly as
  > written (ã, ç, é, ê, ô, etc.). (2) Infer document structure — use `##` for main
  > section headings, `###` for sub-sections, `- ` for bullet lists, numbered lists for
  > ordered items, and pipe-delimited tables for tabular data. (3) Wrap key terms or
  > highlighted phrases in `==term==` (double-equals). (4) Do NOT add commentary,
  > preamble, or trailing notes — output ONLY the Markdown. (5) If a word is genuinely
  > illegible, write `[?]` in its place.

  User turn: single `image` content block (base64 JPEG).

- **Post-processing** (`packages/core/src/ocr/postprocess.ts`):
  - Strip any leading/trailing preamble lines that start with "Here is", "Below is", etc.
  - Normalise Unicode to NFC (preserves accents; fixes some model output encoding quirks).
  - Count words (split on whitespace, exclude Markdown syntax tokens) → `wordCount`.
  - Attempt to detect language pair: scan the first 200 words for Portuguese diacritics
    (ã/ç/ê/ô) → `detectedLang = "pt-BR → en"` if found, else `"unknown"`.
  - Extract OCR confidence if the model returns a `[?]` count:
    `ocrConfidence = Math.round((1 - unknownCount / wordCount) * 100)`.

## Risks / open questions

- **Bedrock model access**: Claude Sonnet inference profiles must be explicitly enabled in the
  Bedrock console for us-east-1 before the first deploy; failure mode is a 400 "model not enabled"
  that surfaces in the error state. Verify and document the exact profile id before seeding the secret.
- **HEIC on Android**: `<input accept="image/heic">` is unreliable on non-Apple devices; canvas
  does not decode HEIC natively on most Android browsers. If HEIC decode fails, catch the error
  and prompt the user to choose JPEG instead (do not attempt a JS HEIC decoder in M4 — out of scope).
- **Large images on low-end phones**: canvas resize of a 12 MP photo can spike memory on old
  Android devices. If `toBlob` or `drawImage` throws, catch + surface the error state.
- **`getUserMedia` on non-HTTPS localhost**: the browser blocks `getUserMedia` on non-HTTPS
  origins in some browsers; local dev must use `localhost` (allowed) or a TLS proxy.
- **Bedrock `ThrottlingException` at scale**: the retry helper uses exponential back-off, but
  repeated throttling on PR stages is possible during heavy CI runs. Consider a 15 s total
  timeout ceiling.
- **Cross-region inference profile id changes**: AWS occasionally revises profile identifiers;
  pinning via the `sst.Secret` (not hardcoded) means a re-seed is the only change needed.

## Manual test plan

Steps to run on the deployed `pr-<N>` site after SST deploy:

1. **Camera capture** — on an iPhone or Android phone, open the capture page. Grant camera
   permission. Point the camera at a handwritten page in good light. Tap the shutter.
   Expected: corner brackets visible in viewfinder; "Edges detected" badge appears after ~1.5 s;
   tapping shutter transitions to the processing screen.

2. **Processing screen** — after shutter tap. Expected: gradient-teal sparkles icon; "Transforming…"
   heading; three-step checklist advances in order; OCR percentage appears in the mono label
   once Bedrock responds.

3. **pt-BR accent preservation** — use a handwritten page containing words like "subjuntivo",
   "ação", "não", "ção", "ê", "ã". Expected: returned Markdown contains the exact accented
   characters; no replacement characters (?) or garbled UTF-8.

4. **Error / retry flow** — photograph a blank or heavily blurred page (cover the lens). Expected:
   error state appears with the blurred-handwriting illustration; "That page came out blurry"
   heading; tips list visible; "Retake" button returns to the viewfinder without a page reload.

5. **File upload path** — tap "Upload"; select a JPEG from the device photo library. Expected:
   same processing → result flow as camera capture; no server error.

6. **IAM least privilege** — in the AWS console, verify the role attached to the Lambda has no
   `s3:*` or `bedrock:*` wildcard; only the scoped actions on the bucket and profile ARN appear.

7. **Missing secret guard** — temporarily comment out the `BEDROCK_INFERENCE_PROFILE_ID` SST
   secret value for a test stage and deploy. Expected: the Next.js server startup log shows a
   hard error referencing the missing secret; the `/capture` route returns 500 immediately rather
   than silently sending an empty model id.

8. **Large image resize** — upload a 10 MP JPEG from a desktop browser via the "Upload" path.
   Expected: network tab shows a PUT to S3 of ≤ 1 MB regardless of original file size.
