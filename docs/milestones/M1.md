# M1 · Design-system port

> Size: L · Depends on: M0

## Goal

Port the TransformMyNotes design system (`.design/_ds/`) into the application as a fully self-contained, reusable component library living in `packages/application/src/components/ui/`. Every token, every component, and both app shells (mobile bottom-nav and desktop sidebar) are implemented as real React + Tailwind + CSS-variable code that faithfully matches the design screens in `.design/app/`. No markup is copied per-page — the system is extracted into reusable primitives that M2+ will consume without touching raw CSS.

By the end of M1, both the mobile and desktop shells render pixel-faithfully against the design mockups; the Markdown-to-HTML renderer handles all syntax variants (headings, `== highlight ==`, bold, italic, inline code, blockquote, ordered/unordered list, table, `---` rule); and a Playwright browser test captures screenshots of the shell and a sample rendered note, committed under `docs/verification/` to prove visual fidelity.

## Architecture & decisions

### Data model additions

None. M1 is purely UI — no new DynamoDB tables, GSIs, or key builders. The dynalite integration harness from M0 is used as-is for the browser test seed.

### API routes

None new. M1 adds a test-only `GET /api/ds-test` route (non-production, behind `if (process.env.NODE_ENV !== 'production')`) that renders a full-page design system showcase (all components + a sample note) — used only by the Playwright `/verify` browser test.

### Infra changes

None. M1 is zero-infra — no new SST resources, secrets, or IAM grants. All changes are in `packages/application/src/` and `packages/marketing/src/`.

### Design screens / components ported

All design references are static mockups for look/feel only — do not copy JSX markup from `.design/app/` into production code. Implement each component from the visual specification using typed React props.

### Component architecture rules

- All components are written in TypeScript with explicit prop interfaces (`interface ButtonProps`). No `any`.
- Components are server-component-safe (no `useEffect` / `useRef` / `useState` at the top level unless the component is explicitly a Client Component via `'use client'`). Interactive components (Toast, Dialog, SegmentedControl, Switch) are Client Components. Display-only components (Badge, Tag, Card, NoteCard, HighlightText, HandNote, Avatar) are Server Components.
- Styling uses Tailwind utility classes for layout/spacing and CSS variables (via `var(--token)` inline or as Tailwind `theme()` / `[var(--token)]` syntax) for colour/shadow/radius — never hardcoded hex colours.
- The `cn()` helper from `clsx` + `tailwind-merge` is used everywhere for conditional class composition.
- All touch targets are `min-h-[44px]` on mobile (matching `--tap-min: 44px` token).
- Focus states use the `--focus-ring` box-shadow token: `ring-[--focus-ring]` or `focus-visible:shadow-[0_0_0_3px_rgba(48,127,112,0.32)]`.
- `prefers-reduced-motion` media query wraps all animation/transition CSS — when the user prefers reduced motion, transitions are set to `duration-0`.

## Risks / open questions

- **Font licensing:** Newsreader, Hanken Grotesk, Caveat, and Spline Sans Mono are all open-source (OFL or Apache 2.0) and available via Google Fonts for self-hosting. Confirm the exact weights used in the design before downloading to avoid missing a variant that causes FOUT. The design system uses Newsreader 400, 600, 700 (regular + italic for each); Hanken Grotesk 400, 500, 600, 700; Caveat 400; Spline Sans Mono 400, 600.
- **`<dialog>` backdrop on Safari:** The CSS `::backdrop` pseudo-element and `backdrop-filter` are supported in Safari 15.4+. If the project must support older Safari, provide a fallback overlay `<div>` rendered alongside the `<dialog>`.
- **SegmentedControl sliding-pill hydration:** The sliding pill's `translateX` position is computed from the selected option's index. If rendered server-side with one value and client-side with another (e.g. URL-driven), a hydration mismatch can occur. Ensure `defaultValue` is used for uncontrolled cases or the component is a Client Component with `suppressHydrationWarning` on the animated element.
- **`renderMarkdown` XSS surface:** The renderer uses `innerHTML` via `dangerouslySetInnerHTML`. The function escapes text nodes, but inline substitution uses `String.replace` on the escaped string — a carefully crafted input could still produce unexpected HTML if the regex patterns are too broad. The unit test covers the basic `<script>` case; consider adding a fuzz test or a DOMPurify pass before trusting user-authored note content from the database.
- **Tailwind purge scope:** Tailwind's content scan must include all component files. If a dynamically constructed class (e.g. `tone-${variant}`) is used, the class name will be purged. Enforce full class names in component code — no template-literal class construction for Tailwind utilities.
- **Logo mark asset:** The `assets/logo-mark.svg` in `.design/_ds/assets/` is a design-system proposal asset, not a production asset. Copy it to `packages/application/public/assets/logo-mark.svg` for M1 (it will be in the public URL at `/assets/logo-mark.svg`). Flag for design review — this logo may be replaced.
