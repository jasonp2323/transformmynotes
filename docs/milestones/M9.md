# M9 · Marketing site

> Size: M · Depends on: M0, M1, Claude Design output in `.design/marketing/`

## Goal

Build the public-facing marketing site at the apex domain `transformmynotes.com` (the existing `packages/marketing` Next.js App Router package, port 3000). The site tells the TransformMyNotes brand story and drives qualified visitors to the app at `app.transformmynotes.com`.

**The visual design is delivered by Claude Design and lives in `.design/marketing/`** (created from the design prompt at `docs/milestones/M9-design-prompt.md`). This milestone is about faithfully implementing that design output — not inventing the look, feel, or design system. Layout, spacing, type hierarchy, color, and motion all come from the committed design in `.design/marketing/`. Implementation should reuse shared UI primitives from M1 (e.g. Button) where they exist in the marketing package; do not import from `packages/core` or `packages/application`.

The marketing site has **no auth, no DynamoDB access, and no contact form** — it has no server-side form handlers. The primary CTA simply links to the app's sign-up/login. **No new `sst.Secret` entries are required** for this milestone.

## In scope

- Hero section: brand headline + subhead, logo/nav, "handwriting → clean note" illustrative visual, "Request access" CTA link (→ `app.transformmynotes.com/signup`) and "Sign in" link (→ `app.transformmynotes.com/login`)
- Feature / benefit section: six benefit cards (Capture, Transform, Search, Review, Groups, Invite-gated access) in a responsive grid — purely informational, no links
- "How it works" three-step narrative section (Snap → Transform → Study)
- "Request access" CTA strip: primary link to signup, secondary "Sign in" link to login — no form
- SEO and social: `<head>` metadata (`title`, `description`, canonical URL), Open Graph tags (`og:title`, `og:description`, `og:image` using a static OG card), `robots.txt`, `sitemap.xml`
- Favicon: SVG favicon and `apple-touch-icon` derived from the logo mark
- Responsive, mobile-first layout matching the design
- Accessibility: WCAG AA contrast on all text, visible focus rings, `alt` text on all images, `prefers-reduced-motion` respected
- Page-level analytics stub: a `<Script>` placeholder comment where a script tag would go so adding analytics later is one-line
- Implementation matches the design output in `.design/marketing/` faithfully

## Out of scope

- Auth, DynamoDB, or Cognito of any kind in the marketing package
- Contact form or any server-side form handlers
- Actual invite/approval management UI (that lives in the admin panel, M4)
- A blog, pricing page, or docs section
- Video or animated GIF assets
- Real analytics integration (placeholder comment only)
- i18n / multi-language copy (the site is English-only for launch)

## Architecture & decisions

### Infra
- No new SST resources. `infra/marketing.ts` already attaches `packages/marketing` at the apex via the shared `sst.aws.Router` defined in `infra/router.ts`. `WEB_DOMAIN` is already declared in `infra/secrets.ts` and used for the apex custom domain; the marketing site needs no other secrets.
- `CLOUDFLARE_API_TOKEN` remains a Console environment variable (not an `sst.Secret`) as documented in CLAUDE.md.
- PR-stage deployments use auto-generated CloudFront URLs (no apex DNS for ephemeral stages).

### CI/CD
- The existing `npm run test:e2e` gate in `deploy.yml` already runs the marketing Playwright suite; this milestone fills it with real tests. No workflow changes needed.
- Offline CI: `playwright.config.ts` must start the marketing dev server (`next dev -p 3000`) before the tests run; no AWS.

### Design fidelity
- All layout, spacing, typography, color, and motion decisions are taken from the committed design output in `.design/marketing/`. Engineers implement what is designed there — they do not invent or override design choices.
- Fonts are self-hosted under `public/fonts/` (already in place) — no Google Fonts CDN dependency, no CI font-fallback risk.

### A11y
- Minimum contrast ratio 4.5:1 for body text (verify against the design's actual color choices).
- All interactive elements: visible `:focus-visible` outline; no `outline: none` without a replacement.
- Semantic HTML: `<header>`, `<main>`, `<section>`, `<footer>`; one `<h1>` per page; logical heading hierarchy.

**1. (S) Page shell & scaffold**

- Favicon tab shows the logo mark in Chromium.
- No TypeScript errors, no ESLint warnings.

**2. (M) Hero section**
Implement the hero exactly as designed in `.design/marketing/`: logo/nav, headline with the emphasized word, supporting sub-headline, handwritten accent line, the illustrative "handwriting → clean note" visual, and the two CTAs as `<a>` links ("Request access" → `app.transformmynotes.com/signup`, "Sign in" → `.../login`, same tab). - Both CTAs are `<a href>` elements linking to `app.transformmynotes.com`; they open in the same tab (no `target="_blank"`).
- Implementation matches the `.design/marketing/` hero design faithfully.

Acceptance criteria:

**5. (S) "Request access" CTA strip**

**6. (S) SEO, Open Graph, and sitemap**
Add a root `layout.tsx` `<head>` with: `<title>TransformMyNotes — your handwriting, transformed</title>`, `<meta name="description">`, `<link rel="canonical">`, Open Graph tags (`og:type`, `og:title`, `og:description`, `og:image` pointing to a static `public/og-image.png` — a 1200×630 PNG that embeds the wordmark on the page background), `twitter:card summary_large_image`. Add `public/robots.txt` (allow all, sitemap pointer) and a `app/sitemap.ts` Next.js sitemap route (only the landing page `/` for now).

Acceptance criteria:
- `curl -s localhost:3000 | grep 'og:title'` returns the correct tag.
- `curl -s localhost:3000/sitemap.xml` returns valid XML with a `<loc>` entry for `/`.
- `curl -s localhost:3000/robots.txt` returns a `Sitemap:` directive pointing to `/sitemap.xml`.
- OG image is present at `localhost:3000/og-image.png` (static file, not a dynamic route).

---

**7. (M) Marketing Playwright E2E suite**
Write or flesh out the committed `e2e/` Playwright tests (`npm run test:e2e`, `playwright.config.ts`) so they run fully offline in CI:

`playwright.config.ts` must use `webServer` to start `next dev -p 3000` (or `next build && next start -p 3000`) before the tests; `baseURL` is `http://localhost:3000`.

Acceptance criteria:

- Both test files (`landing.spec.ts` and `a11y.spec.ts`) are committed under `e2e/marketing/`.
- The axe test asserts `violations.filter(v => v.impact === 'critical').length === 0`.
- CI (the `deploy.yml` gate) is green on a PR that touches only `packages/marketing`.

## Risks / open questions

- **Implementation blocked on design output**: this milestone cannot begin implementation until the Claude Design output is committed to `.design/marketing/`. Confirm that output is in place before starting sub-issues 1–5.
- **OG image**: a static PNG is simplest; if a dynamic `/api/og` route using `@vercel/og` is preferred later, it can be added in a follow-up — do not block M9 on it.
- **`app.transformmynotes.com` not yet live on M9**: the marketing CTA links hardcode `app.transformmynotes.com`. If M9 is deployed before the app subdomain is live (M10 DNS cutover), links will 404. Consider using a `/coming-soon` stub or adding an `[skip deploy]` escape on early M9 PRs.
- **"Sign in" link placement**: whether the "Sign in" link appears in the header at all times or only after scrolling past the hero is a design decision resolved by the committed `.design/marketing/` output — engineers implement what the design specifies.

## Manual test plan

Perform on the deployed `https://transformmynotes.com` production URL after M10 DNS cutover (or on a `pr-<N>` CloudFront URL during development):

1. **Landing page load** — navigate to the root URL in Chrome on a mobile emulation (390px). Expected: page renders matching the design (background, logo in nav, headline, accent phrase, "Request access" and "Sign in" links visible without scrolling).
2. **Desktop layout** — widen to 1200px. Expected: hero and feature cards match the design's wider-viewport layout.
3. **CTA links** — click "Request access". Expected: navigates to `app.transformmynotes.com/signup`. Click "Sign in". Expected: navigates to `app.transformmynotes.com/login`. Both open in the same tab.
4. **Favicon and OG** — observe the browser tab favicon (logo mark). In a new tab open `https://transformmynotes.com/og-image.png`. Expected: 1200×630 image with the wordmark.
5. **SEO tags** — open DevTools → Elements, inspect `<head>`. Expected: `<title>`, `<meta name="description">`, `og:title`, `og:image` tags present.
6. **Keyboard navigation** — tab through the page from top. Expected: visible focus ring on every interactive element (nav links, CTA links). No focus traps. Tab order is logical top-to-bottom.
7. **Reduced motion** — in DevTools → Rendering → Emulate CSS media feature → `prefers-reduced-motion: reduce`. Reload. Expected: no animated sweeps or transition lifts; the page is fully readable without any motion.
8. **Contrast** — use DevTools color picker to sample body text against the page background. Expected: contrast ratio ≥ 4.5:1 (matches the design's accessible color choices).
