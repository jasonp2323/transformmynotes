# M10 · Hardening & launch

> Size: L · Depends on: M0, M1, M2, M3, M4, M5, M6, M7, M8, M9

## Goal

Take TransformMyNotes from a feature-complete state to a hardened, production-ready service. This milestone is the final gate before real users are invited. It covers four interlocking concerns: (1) accessibility — a systematic WCAG AA pass across both `packages/marketing` and `packages/application`; (2) resilience — retry/resumable upload and OCR pipelines so transient failures do not lose user work; (3) security and cost hygiene — least-privilege IAM, resource tagging for cost attribution, and a caching/model-tier pass; and (4) operational readiness — seeding all secrets, verifying Resend's sending domain on `transformmynotes.com`, completing the DNS cutover to the production custom domains, enabling and passing the opt-in authed application `[E2E]` suite, filling remaining `{{PLACEHOLDER}}` tokens, and deleting `TEMPLATE-SETUP.md`.

This milestone is intentionally not a feature milestone. No new user-facing capabilities are built. Every sub-issue tightens, verifies, or connects what already exists.

## In scope

- **WCAG AA accessibility pass**: keyboard navigation, focus ring fidelity, color contrast, reduced-motion, skip-nav link, semantic landmark roles, alt text, form labels, error announcements — across every page in both `packages/marketing` and `packages/application`
- **Resilient uploads**: exponential-backoff retry (up to 3 attempts, jitter) on S3 `PutObject`; multipart upload for files > 5 MB so a network blip mid-upload can resume; user-facing "Uploading… retry" state in the UI
- **Resilient OCR**: retry wrapper around Bedrock `InvokeModel` calls (up to 3 attempts, `ThrottlingException` + `ServiceUnavailableException` triggering backoff); idempotent job status in DynamoDB so a re-invoked Lambda does not double-charge or produce duplicate notes
- **Least-privilege IAM audit**: review every `permissions` block in `infra/application.ts` and `infra/jobs.ts`; replace any wildcard (`*`) resource or action with the minimally scoped ARN; scope `bedrock:InvokeModel` to the specific cross-region inference profile ARN, S3 actions to the single upload bucket ARN + prefix, DynamoDB actions to the specific table ARN + its index ARNs, Cognito admin actions to the specific user pool ARN
- **Resource tagging**: apply `{ Project: "TransformMyNotes", Stage: $app.stage }` tags to every SST resource (Nextjs, Bucket, Table, CognitoUserPool, Router, any EventBus/Queue/Function) via SST's `tags` config in `sst.config.ts`; verify in the AWS Console that Cost Explorer can be filtered by `Project=TransformMyNotes`
- **Cost/performance pass**: default image resize on upload (max 2048px longest edge, JPEG quality 85, before S3 `PutObject`); Bedrock model tier locked to `anthropic.claude-3-5-sonnet-20241022-v2:0` (or the current Sonnet cross-region inference profile); CloudFront cache-control headers for marketing static assets (`max-age=31536000, immutable` for hashed assets, `no-store` for HTML); Next.js `<Image>` component for all `<img>` tags in marketing
- **Secrets seeding checklist**: confirm every `sst.Secret` (and the `CLOUDFLARE_API_TOKEN` env var) is seeded in both the SST Console production environment and the fallback environment; document the exact secret names and Console environment names in the production runbook section of this doc
- **Resend sending domain**: verify `transformmynotes.com` as a Resend sending domain (add DNS SPF/DKIM TXT records in Cloudflare) so `INVITE_FROM_ADDRESS` can be `noreply@transformmynotes.com`; confirm email deliverability with a test send
- **Production DNS cutover**: set `WEB_DOMAIN=transformmynotes.com` in the production Console environment; deploy `production` stage via `npx sst deploy --stage production`; add Cloudflare DNS records for apex (`transformmynotes.com` → CloudFront via CNAME/ALIAS), `app.transformmynotes.com`, and `auth.transformmynotes.com` (Cognito Hosted UI); verify ACM certificates issue successfully (grey-cloud / DNS-only Cloudflare proxy required for wildcard ACM challenge)
- **`{{PLACEHOLDER}}` token fill**: replace all remaining `{{PLACEHOLDER}}` tokens in `CLAUDE.md`, `.claude/`, and workflow files (`{{REPO}}`, `{{REPO_OWNER}}`, `{{GH_USERNAME}}`, `{{DEFAULT_BRANCH}}`, `{{PKG_SCOPE}}`, `{{WEB_DOMAIN}}`, `{{STAGING_DOMAIN}}`, `{{AWS_ACCOUNT_ID}}`, `{{AWS_DEPLOY_ROLE_ARN}}`, `{{PROJECT_NAME}}`, `{{PROJECT_NUMBER}}`, `{{PROJECT_ID}}`, all field/option IDs); delete `TEMPLATE-SETUP.md`

## Architecture & decisions

### Infra changes

**IAM — least privilege (infra/application.ts, infra/jobs.ts)**
Every `permissions` entry must use the exact resource ARN, not `"*"`. Required scopes:
- `bedrock:InvokeModel` → ARN of the specific cross-region inference profile for Claude 3.5 Sonnet: `arn:aws:bedrock:us-east-1::foundation-model/anthropic.claude-3-5-sonnet-20241022-v2:0` and its inference profile variant. Do not use `arn:aws:bedrock:*:*:*`.
- `s3:PutObject`, `s3:GetObject`, `s3:DeleteObject` → `arn:aws:s3:::${bucket.name}/uploads/*` (prefix-scoped, not the entire bucket).
- `dynamodb:GetItem`, `PutItem`, `UpdateItem`, `DeleteItem`, `Query` → `arn:aws:dynamodb:us-east-1:${account}:table/${table.name}` plus `arn:aws:dynamodb:us-east-1:${account}:table/${table.name}/index/*` for GSI queries.
- `cognito-idp:AdminInitiateAuth`, `AdminGetUser`, `AdminUpdateUserAttributes`, `AdminDisableUser`, `AdminDeleteUser` → `arn:aws:cognito-idp:us-east-1:${account}:userpool/${pool.id}`.
- `kms:Decrypt`, `kms:GenerateDataKey` (if KMS is used for BYOK) → the specific key ARN.

No `"Resource": "*"` anywhere in the deployed IAM policies. Verify by inspecting the synthesized CloudFormation template (`npx sst diff --stage production`) before deploying.

**Resource tagging (sst.config.ts)**
Add at the top of the `app()` function, before any resource definitions:
```ts
$app.tags({ Project: "TransformMyNotes", Stage: $app.stage });
```
This propagates to all SST-managed resources. Custom Lambda/IAM resources created outside SST must have tags added manually in their respective `infra/` modules.

**Bedrock model tier**
The `BEDROCK_MODEL_ID` environment variable/secret that selects the model is **introduced in M4** (`infra/secrets.ts`, read via `Resource.BEDROCK_MODEL_ID.value`, throws if unset). M10 only *audits and locks* it: confirm it is declared and seeded in both Console environments, and that its value is a Sonnet cross-region inference profile (e.g. `us.anthropic.claude-sonnet-4-5-20251120-v1:0`) — not Opus (Sonnet's vision is sufficient and ~5× cheaper for OCR). Because it is parameterized, an AWS model-version bump is a secret update, not a code deploy.

**Resend sending domain**
Add the Resend-provided SPF and DKIM DNS TXT records to the `transformmynotes.com` Cloudflare zone (DNS-only, grey cloud). Verify in the Resend dashboard. Set `INVITE_FROM_ADDRESS=noreply@transformmynotes.com` in both SST Console environments after verification.

**Production DNS cutover sequence** (order matters to avoid ACM timeout):
1. Set Cloudflare records to DNS-only (grey cloud / proxy disabled) for `transformmynotes.com`, `app.transformmynotes.com`, `auth.transformmynotes.com`.
2. Deploy `production` stage: `npx sst deploy --stage production`. SST creates ACM certificate + triggers DNS validation.
3. Add the ACM CNAME validation records in Cloudflare (DNS-only). Wait for ACM to reach `ISSUED` status (typically 2–5 min).
4. Confirm CloudFront distributions are active. Point apex and subdomain CNAME/ALIAS records at the CloudFront domains surfaced in the deploy output.
5. Re-enable Cloudflare proxy (orange cloud) on `transformmynotes.com` and `app.transformmynotes.com` after ACM is issued and CloudFront is responding correctly. Keep `auth.transformmynotes.com` DNS-only (Cloudflare free SSL does not cover second-level wildcards).
6. Verify HTTPS on all three domains in browser.

**Custom Cognito Hosted UI domain**
In `infra/auth.ts`, set the custom domain `auth.transformmynotes.com` behind the `isProd` guard (`$app.stage === "production"`). Ephemeral stages continue to use the default Cognito domain.

### Security specifics

- No hardcoded ARNs, account IDs, or secret values in committed code. All are read from `sst.Resource` at runtime.
- All `sst.Secret` values fail loudly if unset (the SST runtime throws on `Resource.X.value` access when the secret is not seeded — verify this behavior in a `pr-<N>` stage by temporarily omitting one secret and confirming the build/startup fails rather than serving a broken experience).
- Image uploads: enforce a maximum file size (10 MB) in the upload route before the S3 `PutObject`; return `413 Payload Too Large` for oversized requests.
- Bedrock response: never surface raw Bedrock error messages to the client — log them server-side (CloudWatch), return a generic `{ error: "Transform failed. Please try again." }` to the UI.
- KMS: if per-user BYOK credentials are encrypted with KMS (M-series milestones), ensure the key policy allows only the Lambda execution role, not `"Principal": "*"`.

### A11y specifics

Audit scope — every rendered page/route in both packages:

**Marketing (`packages/marketing`)**
- `/` (landing): `<h1>` uniqueness, heading hierarchy, landmark regions, alt text on logo SVG (use `role="img" aria-label`), CTA button contrast, focus ring on all interactive elements, no `tabindex` values > 0.

**Application (`packages/application`)**
- `/login`, `/signup`: form labels, error announcements, autocomplete attributes (`autocomplete="email"`, `"current-password"`, `"new-password"`), Cognito redirect handling.
- `/dashboard`: skip-nav link (`<a href="#main-content" class="sr-only focus:not-sr-only">`), card focus rings, "no notes yet" empty state not announced as an error.
- `/notes/[id]`: the Original/Clean toggle (`<SegmentedControl>`) must be keyboard-operable (arrow keys within the group); `<mark>` highlights must have `aria-label` or surrounding context; Markdown render must not nest interactive elements.
- `/notes/[id]/upload`: file input with `<label>`, drag-drop zone with `role="button" tabindex="0"` and `onKeyDown` Enter/Space handler, upload progress region as `aria-live="polite"` + `role="status"`.
- `/review`: flashcard flip must be keyboard-operable (Enter/Space); front/back content changes announced via `aria-live="assertive"`.
- `/admin`: data tables must have `<th scope="col">` headers; sortable columns need `aria-sort`; action buttons per row need unique accessible names (e.g. `aria-label="Approve user Jane Doe"`).

Tools: `@axe-core/playwright` in the E2E suite; manual keyboard pass; NVDA+Chrome and VoiceOver+Safari spot-checks documented in the PR.

### Cost / performance

- **Image resize before S3 upload**: in the upload server route (or a pre-upload client step using the Canvas API), resize to max 2048px on the longest edge, re-encode as JPEG at quality 85. This caps S3 storage and Bedrock image payload size. Note: Canvas API is available in the browser; for server-side resize use the `sharp` npm package (already a common Next.js dependency).
- **Bedrock model**: use `us.anthropic.claude-3-5-sonnet-20241022-v2:0` (the us-east-1 cross-region inference profile). Do not use Opus for OCR — Sonnet's vision capability is sufficient and ~5× cheaper. The model ID is parameterized via `BEDROCK_MODEL_ID` secret so it can be changed without a deploy.
- **CloudFront cache headers**: Next.js automatically adds `Cache-Control: public, max-age=31536000, immutable` to hashed `_next/static/` assets. Verify this is not overridden. The marketing HTML pages should carry `Cache-Control: no-store` (the default for Next.js server-rendered pages) so CDN does not cache stale content.
- **DynamoDB on-demand billing**: all tables use PAY_PER_REQUEST billing (SST default for `sst.aws.Dynamo`). No provisioned capacity to over-provision.

**5. (M) Resilient OCR (Bedrock retry + idempotent job)**
Wrap the `bedrock.invokeModel` call in a retry helper: 3 attempts, exponential backoff (1s, 2s, 4s), jitter ±200ms, retry only on `ThrottlingException` and `ServiceUnavailableException` (do not retry `ValidationException` or `AccessDeniedException`). Store job status in DynamoDB with states `PENDING → PROCESSING → DONE | FAILED` keyed by `noteId`. On Lambda re-invocation (e.g. SQS retry), check DynamoDB status first — if already `DONE`, skip re-processing and return early (idempotent). On `FAILED` after 3 attempts, write the error summary (not the raw Bedrock error) to DynamoDB and surface "Transform failed — please try again" in the UI. Add a unit test for the retry helper and a unit test for the idempotency guard.

Acceptance criteria:
- Unit test: mock Bedrock to throw `ThrottlingException` twice then succeed; assert 3 total calls; assert the final result is the successful response.
- Unit test: with job status `DONE` in the mock store, assert the processing function returns early and Bedrock is never called.
- Integration test: write a `PROCESSING` status record to dynalite, call the idempotency guard, confirm it short-circuits.
- `npm run test:unit` and `npm run test:integration` pass.
- Bedrock errors are logged to `console.error` (CloudWatch) but the response to the client is only `{ error: "Transform failed. Please try again." }` — no raw Bedrock message in the response body (asserted in a unit test).

## Risks / open questions

- **ACM cert issuance latency**: ACM DNS validation can take up to 30 minutes on first issuance. Allocate time for this in the cutover window; keep the old DNS records until the cert is `ISSUED` to avoid downtime.
- **Cloudflare proxy and ACM**: ACM cannot issue certs through Cloudflare's proxy (orange cloud) for custom-domain CloudFront distributions. During cutover the records must be DNS-only (grey cloud). After the cert is issued and CloudFront is serving traffic, the proxy can be re-enabled for HTTP→HTTPS redirect and DDoS protection — but only on routes that are not direct Cognito callbacks.
- **`auth.transformmynotes.com` must stay DNS-only**: Cloudflare's free Universal SSL does not cover second-level wildcards like `auth.transformmynotes.com`. This record must remain proxied=false permanently.
- **Cognito Hosted UI domain change**: once a custom Cognito Hosted UI domain is set, changing it requires deleting and recreating the user pool (destructive). Lock in `auth.transformmynotes.com` before any production users are created.
- **`cognito-local` version compatibility**: pin the `cognito-local` npm package to a specific version in `devDependencies` so CI does not break on an upstream breaking change.
- **Bedrock model ID changes**: AWS periodically deprecates specific model version IDs. Parameterizing the model ID as `BEDROCK_MODEL_ID` secret mitigates this — a version bump is a secret update, not a code deploy.
- **Canvas API resize in mobile Safari**: the Canvas API for image resize is well-supported but some very old iOS versions have memory limitations. Add a try/catch that falls back to sending the original file if Canvas resize throws — with a console warning but no user-visible error.
- **Open question**: should the production Cognito user pool have MFA enabled at launch? If yes, the Hosted UI and the `InitiateAuth` flow in the E2E suite need to handle the MFA challenge step. Recommendation: launch without MFA (OPTIONAL), add it as a post-launch hardening task.
- **Open question**: are there any existing `pr-<N>` stages that need to be torn down before the DNS cutover to avoid stale CloudFront distributions claiming the ACM cert? Run `npx sst remove --stage pr-<N>` for all open ephemeral stages before the production deploy.
