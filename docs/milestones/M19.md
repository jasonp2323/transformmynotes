# M19 · Admin AI settings — runtime-configurable generation

> Size: L · Depends on: M3, M13

## Goal

Give admins a dashboard surface to tune every AI generation parameter — system
prompts, model selection, inference config, guardrail caps, audio voice, and
per-material-type enable/kill-switch toggles — **without a redeploy**.

Today `packages/core/src/ocr/bedrock.ts` and the M13-introduced
`packages/core/src/study/config.ts` resolver (`resolveAiConfig()`) read model
ids and prompts directly from SST secrets / env vars. M19 moves the live values
into a `CONFIG#AI` DynamoDB item that the resolver deep-merges over those
secret defaults, adds a full version-history audit trail, and wires a complete
admin form at `/admin/ai-settings` that any admin can operate without touching
AWS or cutting a deploy.

## In scope

- **`CONFIG#AI` data model** in the existing `UserData` table: `PK=CONFIG#AI,
  SK=CURRENT` (active config) plus `PK=CONFIG#AI, SK=VERSION#<zero-padded seq>`
  (immutable history snapshots). Key builders added to
  `packages/core/src/db/keys.ts`.
- **DB-backed `resolveAiConfig()`** in `packages/core/src/study/config.ts`:
  reads `CURRENT`, deep-merges over secret/env defaults (fail-loud only when a
  required field is absent from both sources), short per-Lambda in-memory cache
  (30–60 s). Cache is busted on every successful `PUT /api/admin/ai-config`
  write.
- **Model allowlist**: a static `AI_MODEL_ALLOWLIST` array in
  `packages/core/src/study/config.ts` (seeded with the vetted Bedrock model ids
  already in use). The `PUT` route validates `modelId ∈ allowlist`. No free-text
  model field accepted.
- **Admin API**: `GET /api/admin/ai-config` and `PUT /api/admin/ai-config`,
  both gated via `getAdminApiUser()` from `@/lib/require-admin`.
- **Admin page** `/admin/ai-settings` under `app/(admin)/admin/ai-settings/
  page.tsx`, added to `AdminShell` nav and `adminActive.ts`.
- **Version history + revert** sub-page/panel: list past `VERSION#` snapshots
  (who/when/version number) and restore one as a new `CURRENT`.
- M13 structured-generation engine + M16 + M18 audio routes wired to call
  `resolveAiConfig()` instead of reading secrets directly.
- Unit tests for the `AiConfig` validation helpers (param-range guards,
  allowlist check) and `resolveAiConfig()` fallback logic.
- Dynalite integration test: write a `CURRENT` config → `resolveAiConfig()`
  returns deep-merged values; delete the `CURRENT` item → resolver falls back to
  secret defaults; write a second config → `VERSION#` items are appended in
  ascending sequence order.
- Browser UI test for the admin AI Settings page per repo convention.

## Out of scope

- Per-group or per-user AI config (future).
- A/B testing or traffic-split across config versions.
- Real-time config push / websocket invalidation (per-Lambda cache expiry is
  sufficient for M19).
- SSE or webhook notifications when the config changes.
- Custom fine-tuned models (allowlist is curated Bedrock hosted models only).
- Prompt templating engine or variable interpolation beyond what M13 already
  supports.

## Architecture & decisions

### `AiConfig` TypeScript interface

Defined in `packages/core/src/study/config.ts` and exported for reuse by the
API routes and the admin page form:

```typescript
export type MaterialType = 'flashcards' | 'quiz' | 'assignment' | 'summary';

export type PollyEngine = 'standard' | 'neural' | 'long-form' | 'generative';

export interface AiConfig {
  // ── Prompts ─────────────────────────────────────────────────────────
  /** Base system prompt used for all material types unless overridden. */
  baseSystemPrompt: string;
  /** Per-material-type prompt; if absent the base prompt is used. */
  promptOverrides: Partial<Record<MaterialType, string>>;

  // ── Model selection ─────────────────────────────────────────────────
  /** Default Bedrock model id (must be in AI_MODEL_ALLOWLIST). */
  modelId: string;
  /** Per-material-type model override; must also be in AI_MODEL_ALLOWLIST. */
  modelOverrides: Partial<Record<MaterialType, string>>;

  // ── Inference parameters ─────────────────────────────────────────────
  maxTokens: number;      // 256–8192
  temperature: number;    // 0.0–1.0
  topP: number;           // 0.0–1.0

  // ── Language ─────────────────────────────────────────────────────────
  /** Default generation language / locale.  */
  languageDefault: 'pt-BR' | 'bilingual' | 'en';

  // ── Guardrails ───────────────────────────────────────────────────────
  /** Max AI generation requests per user per UTC day. */
  perUserDailyGenerationCap: number;   // 1–500
  /** Max notes processed in a single batch run. */
  maxNotesPerRun: number;              // 1–100
  /** Approximate input token budget per call. */
  tokenBudget: number;                 // 256–32768

  // ── Audio (Polly) ────────────────────────────────────────────────────
  pollyVoiceId: string;      // e.g. "Camila", "Vitoria", "Joanna"
  pollyEngine: PollyEngine;
  speedRate: string;         // SSML rate: "slow"|"medium"|"fast"|"x-slow"|"x-fast"|"100%"

  // ── Feature flags ────────────────────────────────────────────────────
  /** Per-material-type generation toggle. */
  enabledMaterialTypes: Partial<Record<MaterialType, boolean>>;
  /** Global kill switch — when false, ALL AI generation is blocked. */
  generationEnabled: boolean;

  // ── Audit (set by the API, not editable by the form) ─────────────────
  version: number;          // auto-incremented integer
  updatedBy: string;        // Cognito sub of the admin who saved
  updatedAt: string;        // ISO-8601
}
```

`AI_MODEL_ALLOWLIST` is a `string[]` constant in the same file, seeded with the
model ids already used by OCR (`BEDROCK_MODEL_ID` secret) and M13 generation.
It is exported so the `GET /api/admin/ai-config` response can surface it to the
form's model dropdown without duplicating the list client-side.

### Data model in `infra/db.ts` and key builders in `keys.ts`

The `CONFIG#AI` items live in the existing `UserData` table — no new table or
GSI is needed. The PK `CONFIG#AI` is outside the `USER#<sub>` namespace so
there is no collision risk.

Add to `packages/core/src/db/keys.ts`:

```typescript
export const aiConfigKeys = {
  /** Active config item. PK=CONFIG#AI, SK=CURRENT. */
  current: () => ({ pk: 'CONFIG#AI', sk: 'CURRENT' as const }),

  /**
   * Immutable history snapshot. SK is zero-padded to 12 digits so
   * lexicographic scan returns versions in ascending integer order.
   *   SK = VERSION#000000000001, VERSION#000000000002, …
   */
  version: (seq: number) => ({
    pk: 'CONFIG#AI',
    sk: `VERSION#${String(seq).padStart(12, '0')}` as const,
  }),

  /**
   * Query parameters for listing all history snapshots in ascending order.
   * Pass directly as additional params to QueryCommand.
   */
  listVersions: () => ({
    KeyConditionExpression: 'pk = :pk AND begins_with(sk, :prefix)',
    ExpressionAttributeValues: { ':pk': 'CONFIG#AI', ':prefix': 'VERSION#' },
    ScanIndexForward: true,
  }),
};
```

No new GSI — all lookups use the known PK + SK prefix.

### DB-backed `resolveAiConfig()`

`packages/core/src/study/config.ts`:

```typescript
// Module-level cache
let _cached: { config: AiConfig; expiresAt: number } | null = null;
const CACHE_TTL_MS = 45_000;  // 45 s — safe for Lambda concurrency

export async function resolveAiConfig(): Promise<AiConfig> {
  if (_cached && Date.now() < _cached.expiresAt) return _cached.config;

  const item = await ddb.get({ ...TableNames.UserData, Key: aiConfigKeys.current() });
  const dbConfig = item.Item as Partial<AiConfig> | undefined;

  const defaults = buildSecretDefaults();   // reads process.env SST_RESOURCE_* + SCREAMING_SNAKE_CASE
  const merged = deepMergeAiConfig(defaults, dbConfig ?? {});

  validateRequired(merged);   // throws if baseSystemPrompt or modelId still unset
  _cached = { config: merged, expiresAt: Date.now() + CACHE_TTL_MS };
  return merged;
}

/**
 * Call this after a successful PUT so the next request sees the new config
 * within the same Lambda instance without waiting for TTL expiry.
 */
export function bustAiConfigCache(): void {
  _cached = null;
}
```

`deepMergeAiConfig` performs a shallow merge at the top level and a deep merge
for the `promptOverrides`, `modelOverrides`, and `enabledMaterialTypes` record
fields — DB values win over defaults on a key-by-key basis.

`buildSecretDefaults()` reads:
- `process.env.SST_RESOURCE_BEDROCK_MODEL_ID_value` → `modelId`
- `process.env.SST_RESOURCE_STUDY_SYSTEM_PROMPT_value` → `baseSystemPrompt`
- etc. (one env var per top-level scalar field introduced by M13)

`validateRequired()` throws a descriptive `Error` (fail-loud) if `modelId` or
`baseSystemPrompt` is empty/missing in the merged result. All other fields have
safe hardcoded fallbacks in `buildSecretDefaults()` so the resolver always
produces a complete `AiConfig`.

### Admin API routes

Both routes live at `packages/application/app/api/admin/ai-config/route.ts`.

#### `GET /api/admin/ai-config`

Calls `getAdminApiUser()` — returns 403 if null. Returns:
```json
{
  "config": { /* current AiConfig, or null when no DB record exists yet */ },
  "allowlist": ["anthropic.claude-3-5-sonnet-…", "…"],
  "paramBounds": {
    "maxTokens":   { "min": 256,  "max": 8192 },
    "temperature": { "min": 0.0,  "max": 1.0  },
    "topP":        { "min": 0.0,  "max": 1.0  },
    "perUserDailyGenerationCap": { "min": 1, "max": 500 },
    "maxNotesPerRun": { "min": 1, "max": 100 },
    "tokenBudget":    { "min": 256, "max": 32768 }
  }
}
```

When no `CURRENT` item exists in DynamoDB, `config` is `null` and the form
initialises from the secret defaults resolved by `buildSecretDefaults()`.

#### `PUT /api/admin/ai-config`

Calls `getAdminApiUser()` — returns 403 if null.

Accepts the full `AiConfig` body (minus the audit fields `version`, `updatedBy`,
`updatedAt`, which are set server-side).

**Validation** (400 on failure):
- `baseSystemPrompt` non-empty string.
- `modelId ∈ AI_MODEL_ALLOWLIST`; same check for every value in `modelOverrides`.
- `maxTokens` in [256, 8192]; `temperature` in [0.0, 1.0]; `topP` in [0.0, 1.0].
- `perUserDailyGenerationCap` in [1, 500]; `maxNotesPerRun` in [1, 100];
  `tokenBudget` in [256, 32768].
- `languageDefault ∈ ['pt-BR', 'bilingual', 'en']`.
- `pollyEngine ∈ ['standard', 'neural', 'long-form', 'generative']`.

**Write sequence** (atomic via two independent `PutItem` calls — no
`TransactWrite` needed since the VERSION item is immutable once written):
1. Read the current `CURRENT` item to get `version` (default 0 if absent).
2. Compute `newVersion = version + 1`.
3. `PutItem` the new `VERSION#<zero-padded newVersion>` snapshot with
   `ConditionExpression: attribute_not_exists(pk)` (guarantees immutability).
4. `PutItem` a new `CURRENT` item (unconditional overwrite) with
   `updatedBy = admin.sub`, `updatedAt = now.toISOString()`,
   `version = newVersion`.
5. Call `bustAiConfigCache()`.
6. Return `{ ok: true, version: newVersion }`.

#### Revert: `POST /api/admin/ai-config/revert`

Body: `{ version: number }`. Reads the `VERSION#<seq>` item, strips the audit
fields, runs the same validation, then writes a new `CURRENT` + a new `VERSION#`
snapshot (so the revert itself is auditable). Returns
`{ ok: true, version: newVersion }`.

### Admin page `/admin/ai-settings`

File: `packages/application/app/(admin)/admin/ai-settings/page.tsx`

Client component (uses `'use client'`). On mount: `GET /api/admin/ai-config` to
populate the form.

**Form sections** (all within `AdminShell`):

| Section | Fields |
|---|---|
| **System prompts** | `baseSystemPrompt` (large textarea); collapsible per-type overrides for each `MaterialType` (`promptOverrides.flashcards` etc.) |
| **Model selection** | `modelId` dropdown (allowlist options); collapsible per-type overrides (`modelOverrides.*`) each also a dropdown |
| **Inference params** | `maxTokens` number input; `temperature` slider 0–1; `topP` slider 0–1 |
| **Language** | `languageDefault` segmented control / select |
| **Guardrails** | `perUserDailyGenerationCap` number input; `maxNotesPerRun` number input; `tokenBudget` number input |
| **Audio** | `pollyVoiceId` text input or select; `pollyEngine` select; `speedRate` select |
| **Feature flags** | Per-`MaterialType` toggle (checkbox/switch) for `enabledMaterialTypes`; `generationEnabled` master kill switch (rendered prominently in danger tone when off) |

**Save flow**: clicking "Save" calls `PUT /api/admin/ai-config`; on success shows
a success toast ("AI config saved — version N"); on error surfaces validation
message from the API response. All inputs disabled while the request is in
flight.

**Nav entry**: add `{ href: '/admin/ai-settings', icon: 'sliders', label: 'AI Settings', description: 'Tune prompts, models, and generation parameters.' }` to:
- `packages/application/app/(admin)/admin/page.tsx` `SECTIONS` array.
- `packages/application/src/components/admin/adminActive.ts` — add
  `if (pathname.startsWith('/admin/ai-settings')) return 'ai-settings';` and
  extend the return type union.

### Version history + revert UI

A collapsible "Version history" panel at the bottom of `/admin/ai-settings`.
Fetches via a new `GET /api/admin/ai-config/versions` route (queries
`aiConfigKeys.listVersions()`, returns an array of `{ version, updatedBy,
updatedAt }` in descending order for display). Each row shows version number,
the admin's `sub` (or display name if resolvable), and a relative timestamp.
A "Restore" button on each row calls `POST /api/admin/ai-config/revert` with
the version number, then refreshes the form state.

### Infra / secrets changes

- **No new DynamoDB table or GSI** — `CONFIG#AI` items live in the existing
  `UserData` table; the `IAM` grants that `application` already holds
  (`dynamodb:GetItem`, `dynamodb:PutItem`, `dynamodb:Query` on `UserData`) are
  sufficient.
- **`AI_MODEL_ALLOWLIST` is a static code constant** — not an `sst.Secret`.
  No new secrets required for M19.
- `infra/secrets.ts`: add `STUDY_SYSTEM_PROMPT` as a new `sst.Secret` if M13
  has not already done so (M19 depends on M13; if M13 declared it, no change
  needed here). Fail-loud if absent and no `CURRENT` item exists in DynamoDB.

## Risks / open questions

- **`STUDY_SYSTEM_PROMPT` secret pre-existence**: M19 depends on M13, which is
  assumed to have introduced this secret. If M13 used a different env-var name,
  `buildSecretDefaults()` must be updated to match. Verify the exact env var name
  before starting sub-issue 1.
- **Lambda concurrency + cache invalidation**: the module-level `_cached`
  variable is per-Lambda-instance. In a burst of concurrent requests, multiple
  instances may each hold a slightly stale config for up to 45 s after a `PUT`.
  This is acceptable for a settings change (not a transactional operation);
  document this behaviour in `config.ts`. A future improvement could use SSM
  Parameter Store's built-in caching client (`aws-sdk` SSM) or ElastiCache.
- **`VERSION#` sequence collision**: the write sequence reads `CURRENT.version`,
  increments, then writes `VERSION#<new>`. Under extremely rapid concurrent
  `PUT` calls, two requests could read the same `version` and attempt to write
  the same `VERSION#` SK. The `ConditionExpression: attribute_not_exists(pk)`
  on the VERSION PutItem prevents a silent overwrite — the second caller will
  get a `ConditionalCheckFailedException` and should return HTTP 409 (conflict:
  "Another save is in progress — please retry"). Document this in the PUT route
  handler.
- **`AI_MODEL_ALLOWLIST` drift**: as Bedrock releases new model versions the
  allowlist will go stale. The initial list is seeded from the models already
  in use; adding new models requires a code change + deploy. An admin-editable
  allowlist (stored in DynamoDB) is a future improvement.
- **Revert to a config with a now-disallowed model**: if the allowlist is
  tightened after a config was saved, a revert to that old config will fail
  validation. The `POST /revert` route must run the same allowlist check as
  `PUT`. Document this as expected behaviour with a clear 400 error message.
- **Audio field dependency on M18**: sub-issue 4 wires M18 audio. If M18 is not
  yet merged when M19 work begins, sub-issue 4 should skip the audio wiring and
  add a follow-up note rather than blocking the milestone.
